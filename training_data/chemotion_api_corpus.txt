# chemotion_api cheat sheet

`chemotion_api` wraps the REST API of a Chemotion ELN. Objects are edited locally and only reach the
server on `save()`. Everything you change through it is changed in a real lab notebook used by real
people, so read before you write, change only what the task asks for, and confirm with the user before
bulk edits or deletions. If a test instance exists, try risky operations there first.

For full method signatures and all property keys, read `references/api.md`.

## Connect

```python
from chemotion_api import Instance

instance = Instance('https://eln.example.org').test_connection().login_token('chemtoken_...')
# test_connection() raises ConnectionError
# API token: ELN > Account & Profile > Account > Authentication Token (needs 2FA). Instance(url, token=...) also works.
# login(user, password) is deprecated (FutureWarning)
```

## Find things

```python
root = instance.get_root_collection()            # the 'All' collection tree
col = root.get_collection('/Projects/Team One')  # raises ModuleNotFoundError if missing
col = root.get_or_create_collection('/Projects/Team One/P 123')  # creates + saves the last level only
sub = col.get_collection('P 123')                # relative to col; './' and '..' do NOT work
for c in root.walk():                            # every collection in the tree, parent before children
    print(c.label, c.get_path())                 # root.sync_root.walk() for shared ones; max_depth=1 = children only
# c.name, c.get_name() and c.get_label() are read-only aliases of c.label

sample = instance.get_sample(12)                 # also get_reaction / get_wellplate / get_research_plan
elem = instance.get_generic_by_label('Device', 3)   # generic element by label (or get_generic_by_name)

for s in col.get_samples(per_page=50):           # get_reactions, get_wellplates, get_research_plans,
    print(s.id, s.short_label, s.name)           # get_generics_by_label(label), get_generics_by_name(name)
```

`get_samples()` does not list samples that are only reactants or solvents of a reaction (server behavior);
reach them via `reaction.reactants` / `reaction.solvents`. `len(es)` is the total on the server; the server
allows at most 100 per page, iteration loads all pages.

Listing and search results are partial. `id`, `name`, `short_label` and `json_data` come from the
listing; the first access to `properties`, `segments`, `analyses`, `attachments` (or `molecule`, `wells`,
`workflow`) loads the full element - one request each. So iterate cheaply over labels, and expect a
request per element once you touch data.

Search (samples and reactions):

```python
from chemotion_api.search.utils import EnumMatch, EnumConnector
hits = (instance.search_sample()
        .add_search_condition(EnumMatch.LIKE, EnumConnector.OR, name='Ethanol', cas='64-17-5')
        .find_max(20).request())
# search_reaction() fields: name, short_label, status, conditions, reaction_type, temperature_in_c,
# duration_in_sec, private_note
```

## Create things

All `new_*` methods return an unsaved object; nothing exists on the server until `save()`.
Elements cannot be created in the root collection ('All'): `root` has no `new_*` methods
(AttributeError). Create them in a real collection, e.g. `root.get_or_create_collection('My data')`.

```python
s = col.new_sample_smiles('CCO')         # molecule from SMILES (server-side lookup)
                                         # elements/ions need brackets: '[Mg]', not 'Mg' (ValueError)
solv = col.new_solvent('CDCl3')          # exact name from instance.get_solvent_list(); KeyError suggests names
r = col.new_reaction(); rp = col.new_research_plan(); wp = col.new_wellplate()
g = col.new_generic_by_label('Device')   # or new_generic(type_name)
s.save()                                 # s.id is an int afterwards (a UUID string before)
```

Setting a molecule (`new_sample_smiles`, `s.molecule = ...`) copies its density (or a `molarity` set on the
`Molecule`) to the sample if the sample has neither a density nor a molarity yet.

## Edit and save

`element.properties` is the main tab. Assign keys; then `save()`. `save(load_after_save=True)` reloads
from the server, which you need before reading back attachments or ids of new sub-objects.

### Samples

```python
from chemotion_api.elements.utils import QuantityUnit

s.properties['external_label'] = 'EtOH batch 3'
s.properties['description'] = 'Stored at 4 °C'
s.properties['purity'] = 0.98            # fraction, 0 < purity <= 1 (not percent)
s.properties['density'] = 0.789          # g/ml; molarity is properties['molarity']['value']
s.set_amount(2.5, QuantityUnit.Gram)     # preferred way to set an amount
print(s.gram, s.mol, s.liter)            # converted amount; None without an amount or when it cannot be
                                         # converted (mol needs a molecular weight, liter a density/molarity)
s.save()
```

- A sample has `target_amount` (planned/used) and `real_amount` (obtained). `set_amount` writes
  `real_amount` for reaction products and `target_amount` otherwise, and clears the other one.
- Units: `QuantityUnit.Gram` ('g'), `Mole` ('mol'), `Liter` ('l'), `Equivalent` (relative to the reaction's
  reference material; starting materials and reactants only). Products accept g, mol (and l with
  density/molarity). `s.allowed_quantity_units()` lists what is valid for this sample. With no unit given and
  none stored, the first allowed unit is used.
- `set_amount(value, unit)`: value first. A unit string must be one of 'g', 'mol', 'l', 'Equivalent'
  (case insensitive); 'gram', 'eq', 'mg', 'mmol', 'ppm' raise ValueError, so convert to g/mol/l yourself.
  There is no `QuantityUnit.Ppm`; ppm is only the concentration of a gas product (see Gas-phase reactions).
- `s.molecule` is a dict-like `Molecule`: `s.molecule['molecular_weight']` or `s.molecule.molecular_weight`
  (read-only); keys: `molecular_weight`, `sum_formular`, `cano_smiles`, `inchikey`, ...
- `s.split()` and `s.copy()` save the original first, then return an unsaved new sample.

### Reactions

```python
r = instance.get_reaction(5)
r.starting_materials.append(instance.get_sample(12))   # appends a SPLIT (saves the original first)
r.reactants.append(instance.get_sample(13))            # split, short label 'reactant'
r.products.append(instance.get_sample(14))             # appends a COPY
r.solvents.append(col.new_solvent('Toluene'))          # solvents are added as they are
# r.starting_materials.append_no_split(sample) adds the sample itself (no split, no pre-saving);
# like append it sets reaction, role and position and keeps/initializes the amount.
# A sample the reaction already holds (any role, same id) raises ValueError; remove it first to move it.

r.reference_sample = r.starting_materials[0]   # equivalents and yields are relative to it
r.reactants[0].set_amount(1.5, QuantityUnit.Equivalent)
r.products[0].set_amount(0.0015, QuantityUnit.Mole)   # real amount; the yield follows from the reference
r.properties['temperature'].add_time_point(0, 30, 0, 80)   # h, min, s, value in valueUnit (°C)
r.properties['status'] = 'Running'      # '', Planned, Running, Done, Analyses Pending, Successful, Not Successful
r.properties['purification'] = ['TLC', 'Filtration']   # unknown values are dropped silently
r.properties['description'] = 'Plain text is converted to Quill.js'
r.properties['vessel_size'] = {'amount': 50, 'unit': 'ml'}
r.save()                                # recomputes equivalents and yields from the amounts
```

The material lists are also `r.properties['starting_materials']` etc. Unknown status values are ignored
on save, so check spelling.

A sample's place in the reaction (`reference`, `equivalent`, `coefficient`, `position`, `waste`,
`show_label`, the gas fields) is stored only by `r.save()`. Change it on the reaction's own material
(`r.starting_materials[0].properties['coefficient'] = 2; r.save()`). On a sample loaded by itself, setting
such a field raises `ValueError`, and `sample.save()` refuses while such a change is pending.
A saved sample's `short_label` and a reaction's `rinchi_string` / `rinchi_web_key` cannot be set (`ValueError`).

### Gas-phase reactions

```python
from chemotion_api.elements.utils import GasType

r.gas_schema = True                                   # first; no save needed before setting gas types
r.starting_materials[0].set_gas_type(GasType.FEEDSTOCK)
r.products[0].set_gas_type(GasType.GAS)
gp = r.products[0].properties['gas_phase_data']       # GasPhaseObj of the gas product
gp.ppm = 9222                                         # concentration in ppm
gp.time_in_h = 12.5
gp.temperature_in_k = 325.65
r.save()
```

- Set gas types on the materials of the reaction (`r.starting_materials[0]`, ...); a sample that is not part
  of a reaction cannot have a gas type.
- FEEDSTOCK and CATALYST only for starting materials/reactants (CATALYST needs a feedstock first), GAS only
  for products. A reaction has at most one feedstock and one catalyst.
- The allowed units change with the gas type, re-read `allowed_quantity_units()`: a FEEDSTOCK takes l, mol,
  Equivalent; a GAS product takes g only (plus l with density/molarity), no mol.

### Reaction variations (Chemotion >= 3.1)

```python
v = r.variations.add_new()                         # starts with the reaction's current amounts
v.properties['temperature']['value'] = 60          # {'value', 'unit': '°C'}; duration unit 'Second(s)'
v.notes = 'run 2'
v.starting_materials[0].set_quantity(2, QuantityUnit.Gram)
v.reactants[0].set_equivalent(1.5)                 # not for the reference material
v.products[0].set_yield(85)                        # percent
v.solvents[0].set_quantity(0.01, QuantityUnit.Liter)
v.segments['Electrochemistry']['Cell']['Electrode type'] = 'disk'
v.link_analyses(r.analyses.by_name('HPLC 2'))      # analysis must already be saved
r.save()
r.variations.remove(r.variations[-1]); r.save()
```

Mixtures (`sample.is_mixture`) cannot be quantified in variations (NotImplementedError).

### Research plans

```python
rp.add_richtext('Plain text')
rt = rp.add_richtext(); rt.add_text('Title\n', header=rt.HeaderType.H1).add_text('bold', bold=True)
t = rp.add_table(); a, b = t.add_columns('Name', 'Yield'); t.add_row('Run 1', **{b: 85})
rp.add_image('./setup.png')        # uploaded on save
rp.save()
# rp.body: list of entries; RichText / Table objects, sample/reaction entries hold Sample/Reaction objects
```

### Wellplates

`wp.wells[col][row]` with col 0-11 and row 'A'-'H'; assigning a sample stores a split of it.
Caution: parsing a wellplate currently splits (and saves) every well sample, so avoid loading and
re-saving wellplates in bulk until that is fixed.

### Generic elements (LabIMotion)

```python
g = instance.get_generic_by_label('Device', 3)
g.properties['General']['Serial number'] = 'X-12'   # properties[layer label][field label]
g.label, g.klass_name, g.klass_version          # 'Device', 'dev', '1.0' (the template)
opt = next(o for o in g.wf_next_options() if o['wf_idx'] == 0 and o['layer_label'] == 'Calibration')
key = g.wf_next(**opt)                          # returns the new layer's key in g.properties
g.properties[key]['Result'] = 'ok'
g.wf_layer(0, 'Calibration')['Result'] = 'ok'   # same layer, addressed by workflow and label/key
g.wf_add_layer('Calibration')  # add a template layer directly (returns its properties key)
g.save()
```

A layer used twice gets a suffix from its layer key (`three.1` -> `properties['Nr 3.1']`), stable across
reloads; `g.wf_workflows()` lists each workflow's layers with `key`, `label` and `properties_key`.
Templates: `instance.generic_manager().get_element('dev', version='1.0')` (also `label=`; reloads every call).
New type: `gm.create_new_element('Micro Biology', 'bug', prefix='MB')` returns a released, active klass; add
`k.properties.add_new_layer(...).add_field(FieldType.TEXT, 'Strain')`, then `k.save(SaveActionType.MINOR)` (see api.md §10).
Ontology terms on fields: `field.ontology = 'CHMO:0000593'` (or `add_field(..., ontology=...)`); search with
`gm.search_ontology_terms('nmr')`; read on elements with `g.field(layer, field).ontology`.

## Segments (extra tabs, all element types)

`element.segments[segment][layer][field]` using the labels shown in Chemotion (duplicates get `.1`, `.2`).
`element.segments.available()` lists the generic segments of the element type.

```python
cell = s.segments.get('Electrochemistry')['Cell']   # .get() ADDS a missing segment;
                                                     # s.segments['X'] is None if not added yet
s.segments.field_type('Electrochemistry', 'Cell', 'Electrode type')   # 'select'
s.segments.options('Electrochemistry', 'Cell', 'Electrode type')      # [{'key', 'label'}]
s.segments.units('Electrochemistry', 'Cell', 'Temperature')           # ['C', 'F', 'K']
cell['Electrode type'] = 'disk'                    # select: key or label (stored as key)
cell['Temperature'] = {'value': 25, 'unit': 'C'}   # system-defined; a bare number gets the default unit
cell['Cycles'] = 3                                 # integer
s.save()                                           # invalid changed values raise ValueError here
```

`segments['Properties']` and `segments['Analyses']` are the same objects as `properties` / `analyses`.

## Analyses, datasets, attachments

```python
ana = s.analyses.add_analyses('NMR')            # name; dict keys: name, description, kind, status, ...
ana['description'] = '1H NMR in CDCl3'
ds = ana.add_dataset('./nmr.zip')               # uploaded on save; metadata filled by a converter profile
s.save()

for ana in s.analyses:
    for ds in ana.datasets:                     # ATTRIBUTE, not ana['datasets']
        print(ds.name, ds.id)                   # dataset dict = metadata only; name/id are attributes
# Analyses and Attachment keys work as attributes too: ana.name == ana['name'], att.filename
        for att in ds.attachments or []:
            att.save_file('./out')

s.attachments.add_file('./report.pdf')          # element attachments
s.save(load_after_save=True)                    # reload, otherwise the new file can't be found
s.attachments.load_attachment(filename='report.pdf').save_file('./out')   # basename, not path
```

`s.attachments` can be None for elements that have no attachment container (e.g. some generic ones).
Converter profiles: `pm = instance.get_profile_manager(); pm.profiles` (property), `pm.get_profile(id)`,
`pm.new_profile_from_file(path).save()`, `profile.delete()`.

## Collections and sharing

Collection tree changes (`add_collection`, `move`, `delete`) are local until `root.save()`
(`get_or_create_collection` saves itself). Shared-with-me collections are under `root.sync_root` and
cannot be moved, deleted or extended.

```python
from chemotion_api.collection import CollectionSharePermission as P
users = instance.find_user_by_name('Smith')                  # top 3 matches
col.share(P.ReadElements, *users, detail_level=10)            # sent immediately; 0-10 per element type
col.get_shares(); col.unshare(*users)                         # unshare() refuses an empty user list
shared.take_ownership()                                       # accept a P.PassOwnership offer (recipient side)
col.metadata() / col.save_metadata({'title': ..., 'creators': [...]})   # DataCite fields
```

v4 renumbered the permission levels (`ReadElements`, `EditElements`, `AddElements`, `RemoveElements`,
`ManageShares`, `PassOwnership`); always use the names, never numbers.

Moving elements between collections is sent immediately (no `root.save()`):

```python
src.move_elements(dest, sample, reaction)   # not from root ('All'): use assign_elements there
root.assign_elements(dest, sample)          # sample is now in both; same element, not a copy
dest.remove_elements(sample)                # stays in 'All'; nothing is deleted
```

## Deleting (ask the user first)

```python
sample.delete()                          # DELETE /ui_state like the UI; True once it is really gone
col.delete_elements(s1, r1)              # several at once; returns the elements the server kept
reaction.delete_analysis(analysis)       # immediate, files cannot be restored
```
v4 withdraws elements from your collections and destroys only those left in none, so an element still
bound to a reaction or shared elsewhere survives. Templates, users, groups and devices need
`confirm=<label or abbreviation>`; there is no "delete all".

```python
screen = col.new_screen(); screen.wellplate_ids.append(plate.id); screen.save()   # plate must be saved
```

`col.get_screens() / get_cell_lines() / get_device_descriptions() / get_sbmm_samples() / get_vessels()`,
`instance.get_screen(id)` etc. Splits: `col.split_samples(...)` (linked subsamples),
`split_wellplates`, `split_device_descriptions`, `split_sbmm_samples`, `split_generic_elements`
(cell lines have no server-side split in this client).
`Sample.split()` alone builds an *unlinked* copy unless it is saved inside a reaction/wellplate.

## Show the user

`element.open()` opens the saved element in the browser (the user must be logged in there);
`element.url()` returns the link - put it in your answer so the user can check the result.

## Pitfalls checklist

- Nothing is persisted without `save()`; check `element.id` is an int afterwards.
- Purity is a fraction (0-1), yields in variations are percent, equivalents are plain factors.
- Appending to starting materials/reactants/products saves the source sample and creates a new sample.
  Use `append_no_split` if you must not create splits.
- A sample can be in a reaction only once: adding one it already holds, in any role, raises `ValueError`.
  A sample of another reaction is accepted, but on save the ELN gives this reaction a split with a new id.
- Segment and property names are the human-readable labels, case-sensitive.
- `ElementSet` (listings) cannot be indexed negatively; with an IRI filter it can only be iterated.
- Most methods added for v4 act **immediately** (no `save()`): moving, sharing, deleting, splitting,
  comments, references, labels, chemicals, measurements, vessels, exports and admin calls.
- Background jobs (export, import, reports) have no job id; the client waits for the matching
  notification. Re-running one creates a second job.
- `ValueError` from `save()` usually means a segment value does not fit its field; the message names the field.
- Changes the ELN would drop without an error are refused with `ValueError`: reaction-link fields
  (`reference`, `coefficient`, `waste`, ...) saved through `sample.save()` instead of `reaction.save()`, a
  saved sample's `short_label`, a reaction's RInChI.
- `requests.exceptions.RequestException` with `401` means the element is not visible to this user.
  Load/save/list failures raise `chemotion_api.connection.ChemotionRequestError` (a `RequestException`;
  `ChemotionServerError` for 5xx) with `status_code`, `url` and `context`, e.g. `saving sample 12`.
- A refusal the server reports inside a success reply (`{"errors": ...}`, `{"error": ...}`,
  `{"success": false}`) raises `chemotion_api.connection.ChemotionRejectedError` (also a `ConnectionError`
  and a `ValueError`): the server's reason is in the message, the decoded reply in `.body`.

## 1. Instance (`from chemotion_api import Instance`)

## 2. Collections (`chemotion_api.collection`)

Paths are unix-like label paths. Absolute paths start with `/`; others are relative to the collection the
method is called on. `.` and `..` are not supported. `case_insensitive=True` ignores case.

```
AbstractCollection (RootCollection, Collection, RootSyncCollection)
  .id / .label / .children
  .name / .get_label() / .get_name()                  # read-only aliases of .label
```

## 3. ElementSet (result of get_samples etc.)

A list subclass loaded page by page (`per_page`). Iterating loads all pages. `es[i]` loads the page and the
full element; `es[:5]` returns a list; negative indices raise TypeError. Elements are partial until their
data is accessed (see SKILL.md). `len(es)` is the total number on the server (server max per_page: 100).
Sample listings omit samples that are only reactants or solvents of a reaction (server behavior).

## 16. Exceptions

| exception | typical cause |
|---|---|
| ConnectionError | server unreachable, collection/profile request failed, share failed |
| PermissionError | login failed; SciFinder-n token missing or expired |
| chemotion_api.connection.TokenExpiredError | PermissionError raised before sending: the login token has expired |
| requests.exceptions.RequestException | element load/save failed; 401 = not visible to this user |
| chemotion_api.connection.ChemotionRequestError | subclass raised by element load/save/list; .status_code, .url, .context, .snippet |
| chemotion_api.connection.ChemotionServerError | the same for 5xx (server bug, often triggered by invalid data) |
| chemotion_api.connection.ChemotionRejectedError | success status, but the body reports a refusal (`{"errors": ...}`, `{"error": ...}`, `{"success": false}`); also ConnectionError and ValueError; .body is the decoded reply |
| IndexError | `ElementSet.page` set to a page that does not exist |
| ModuleNotFoundError | collection path does not exist |
| ValueError | invalid segment value, unit not allowed, unknown generic type/label, generic id of another type, equivalents without a reference amount in mol, unsaved element in url()/open(), SMILES the server cannot resolve ('Mg' instead of '[Mg]'), a change the ELN would drop (reaction-link field via sample.save(), saved sample's short_label, reaction RInChI) |
| KeyError | sample has no reaction; unknown segment/field name |
| StopIteration | by_name/by_id/dataset_by_name found nothing |
| NotImplementedError | quantities of mixtures in variations |

===== docs/Admin.rst =====
Administration
==============

Some operations require administrator (or device) privileges; the server returns ``401`` otherwise.

Device management
-----------------

Devices are created and listed through :class:`chemotion_api.user.Admin`, which
:meth:`chemotion_api.Instance.get_user` returns when the logged-in user is an administrator.

.. code-block:: python

    admin = instance.get_user()                             # an Admin, when logged in as one
    device = admin.create_device("Device Name", "ABC")      # admin only
    device.delete()

:meth:`~chemotion_api.user.Admin.create_device` returns a typed :class:`~chemotion_api.user.Device`
and raises when the server reports an error — note that a rejected ``name_abbreviation`` comes back
as ``201`` with an ``errors`` body rather than as a failure status.

.. warning::
   **A device you create does not appear in** :meth:`~chemotion_api.user.Admin.fetchDevices`.
   The two read different things on the server: creation writes a row to the ``devices`` table,
   while ``fetchDevices()`` lists *users* whose type is ``Device`` — a separate, older concept
   that happens to share the name. This is a server-side inconsistency, not something this client
   can paper over; a created device is visible through ``GET /api/v1/admin_devices``.

:class:`chemotion_api.user.DeviceManager` covers group membership only
(:meth:`~chemotion_api.user.DeviceManager.add_users_to_group`); it does not create devices.

===== docs/Analyses.rst =====
Analyses
==========
The Analyses object represents the Analyses tab in the Chemotion user interface.
It contains all measurement data and metadata associated with the elements.

Each element has an :class:`chemotion_api.elements.abstract_element.AnalysesList` (``element.analyses``).
An analysis contains datasets; a dataset contains the measurement files and a metadata set, which Chemotion fills
automatically if a converter profile (:meth:`chemotion_api.Instance.get_profile_manager`) matches the uploaded file.
New analyses and datasets are created and uploaded when the element is saved.

.. code-block:: python

    sample = instance.get_sample(1)
    analysis = sample.analyses.add_analyses('NMR')
    analysis['description'] = '1H NMR in CDCl3'
    analysis.add_dataset('./nmr_data.zip')
    sample.save()

Note that the datasets of an analysis are an attribute (``analysis.datasets``), not a dict key, and that a
dataset's dict holds only its metadata set; its name is ``dataset.name``.

.. code-block:: python

    for analysis in sample.analyses:
        print(analysis['name'], analysis['kind'] if 'kind' in analysis else '')
        for dataset in analysis.datasets:
            print('  ', dataset.name, dataset.id, [a['filename'] for a in dataset.attachments or []])

Converter profiles
------------------

The metadata set of a dataset is only filled automatically if a converter profile matches the uploaded file.
Profiles are managed with the :class:`chemotion_api.converter.ProfileManager`:

.. code-block:: python

    pm = instance.get_profile_manager()
    for profile in pm.profiles:          # a property, not a method
        print(profile.id, profile.title)
    profile = pm.new_profile_from_file('./my_profile.json')
    profile.save()

===== docs/CellLineDetails.rst =====
Cell line
==========

A cell-line sample is a quantity of cells: amount, unit, passage, contamination. It belongs to a
cell-line **material**, the cell line itself, which every sample of it shares: name, source,
organism, tissue, growth medium and so on. The client keeps the two apart. ``properties`` holds
the sample's own fields and :attr:`~chemotion_api.elements.cell_line.CellLine.material` the
shared ones.

Create one with :meth:`chemotion_api.collection.Collection.new_cell_line`, naming the material
and its source. An existing material with that name and source is reused; otherwise saving
creates one. ``amount``, ``unit`` and ``passage`` must be set before saving. Fetch one with
:meth:`chemotion_api.Instance.get_cell_line` and list them with
:meth:`chemotion_api.collection.Collection.get_cell_lines`.

.. code-block:: python

    line = col.new_cell_line('HeLa', source='ATCC')
    line.properties['amount'] = 1_000_000
    line.properties['unit'] = 'cells'
    line.properties['passage'] = 3
    line.material['organism'] = 'Homo sapiens'
    line.save()

How the material behaves on save:

* Changing the material's ``name`` or ``source`` links the sample to another material, which is
  created if none matches.
* Every save sends the full material, so a save that only changed the sample never re-links it.
* The ELN applies changes to the material's other fields only when you created that material. For
  a material someone else created, it ignores the change while reporting success. The client
  checks this first and raises ``PermissionError`` instead.
* A change to the material shows on every sample of that cell line.

    :members:


===== docs/Collection.rst =====
Collection
==========


Collections are the main tool given by the Chemotion system to organize elements.
In the Python API, collections are separated in different classes. The root collection
is the basic element to work with collections.

Collections are addressed by unix-like paths built from their labels, e.g. ``'/Projects/Team One'``.
The label can also be read with the aliases ``name``, ``get_label()`` and ``get_name()``.
Paths starting with ``/`` are absolute, all other paths are relative to the collection the method is called on.
Changes to the collection tree (add, move, delete) are only sent to the server when
:meth:`chemotion_api.collection.RootCollection.save` is called;
:meth:`chemotion_api.collection.Collection.get_or_create_collection` saves right away.

.. code-block:: python

    root = instance.get_root_collection()
    col = root.get_or_create_collection('/Projects/Team One')
    col.add_collection('P 124')
    col.get_collection('P 122').move('/Done Projects')
    root.save()

To iterate over the whole collection tree (or a subtree) use
:meth:`chemotion_api.collection.RootCollection.walk`. It walks depth-first and yields a parent
before its children:

.. code-block:: python

    root = instance.get_root_collection()
    for col in root.walk():                      # every owned collection
        print(col.get_path(), len(col.get_samples()))
    for col in root.sync_root.walk():            # every collection shared with you
        print(col.get_path())
    sub = root.get_collection('/Projects')
    list(sub.walk(include_self=True, max_depth=1))   # '/Projects' and its direct children

Elements are moved between collections with
:meth:`chemotion_api.collection.AbstractCollection.move_elements`,
:meth:`chemotion_api.collection.AbstractCollection.assign_elements` and
:meth:`chemotion_api.collection.AbstractCollection.remove_elements`
(or the element methods ``move_to``, ``assign_to`` and ``remove_from``). These requests are sent right away.
Assigning adds the same element to a second collection, it does not duplicate it.
Elements cannot be moved or removed from the root ('All') collection:

.. code-block:: python

    src = root.get_collection('/Projects/Team One')
    dest = root.get_collection('/Done Projects')
    sample = src.get_samples()[0]
    src.move_elements(dest, sample)       # or sample.move_to(dest, src)
    root.assign_elements(src, sample)     # or sample.assign_to(src)
    src.remove_elements(sample)           # or sample.remove_from(src)


Export and import
*****************

A collection can be exported in the ELN's own archive format, the same ZIP its web interface
produces, with :meth:`chemotion_api.collection.Collection.export_zip`. The ELN builds the archive
in the background; the method waits for it and saves it. Such an archive is imported with
:meth:`chemotion_api.Instance.import_zip`, which returns the collections it created. This is
Chemotion's native format, not ``.eln``.

.. code-block:: python

    archive = col.export_zip('project.zip')
    new_collections = instance.import_zip(archive)

===== docs/DeviceDescriptionDetails.rst =====
Device description
===================

A device description records an instrument: its type, vendor, version, location, operators and
how it is used. Create one with
:meth:`chemotion_api.collection.Collection.new_device_description`, fetch one with
:meth:`chemotion_api.Instance.get_device_description`, and list them with
:meth:`chemotion_api.collection.Collection.get_device_descriptions`.

``properties`` holds the commonly used fields, such as ``name``, ``serial_number``,
``vendor_company_name``, ``device_type_name``, ``room`` and ``general_tags``. Every field is
optional. The ELN stores many more, such as maintenance schedules; fields the client does not
expose are kept unchanged when you save.

.. code-block:: python

    device = col.new_device_description()
    device.properties['name'] = 'NMR 400'
    device.properties['vendor_company_name'] = 'Bruker'
    device.properties['general_tags'] = ['nmr']
    device.save()

    for device in col.get_device_descriptions():
        print(device.properties['name'], device.ontology_terms())

``ontology_terms()`` returns the ontology annotations an ELN administrator picked for the device,
as ``{'iri': …, 'label': …}`` entries. If the ELN refuses to create a device description,
``save()`` raises ``ValueError`` with the server's reasons.

===== docs/Elements.rst =====
Elements
==========

The API can handle different kinds of elements from Chemotion.
It can read and write samples, reactions, wellplates, research plans, screens, cell lines,
SBMM samples and device descriptions, as well as LabIMotion generic elements.

How to load Elements
******************************

Single elements can be fetched directly from the instance,
whereas lists of elements must be fetched by a collection.
The documentation for these methods can be found in the corresponding sections
(:mod:`chemotion_api.collection.Collection` & :mod:`chemotion_api.Instance`).

Let's construct an example based on Samples.
To load a single sample you can use :meth:`chemotion_api.Instance.get_sample`.
However, to do so you need to know the exact Database Id of the Sample.

.. code-block:: python

    try:
        sample = instance.get_sample(3)
    except requests.exceptions.RequestException as e:
        pass

To load all elements within a list use :meth:`chemotion_api.collection.Collection.get_samples`.
This method returns an Object of class ElementSet

.. autoclass:: chemotion_api.elements.ElementSet
    :members: page, iter_pages, next_page, prev_page, load_element

.. code-block:: python

    try:
        for sample in instance.get_root_collection().get_collection('Main Test').get_samples():
            pass # DO something
    except requests.exceptions.RequestException as e:
        pass

The elements are loaded lazily, page by page, with 10 elements per page by default.
You can change the page size with the *per_page* argument of the get methods
(e.g. ``col.get_samples(per_page=50)``). All get methods also accept *updated_from_date* and
*updated_to_date* to fetch only elements updated in a time range.

Alternatively, elements can be loaded using their JSON-LD *@id*.
Use the method :meth:`chemotion_api.Instance.get_json_ld_id`.
This id contains its origin host, type and DB id.
The following nonsense code snippet introduces the workflow:

.. code-block:: python

    try:
        sample_A = instance.get_sample(3)
        sample_B = instance.get_json_ld_id(sample_A.json_ld['@id'])
        assert sample_A == sample_B
    except requests.exceptions.RequestException as e:
        pass


The JSON-LD alternative for loading lists of elements uses
the JSON-LD property *@type*: :meth:`chemotion_api.collection.Collection.get_elements_of_iri`.
This type contains the version and the element type. All types known by the server are listed by
:meth:`chemotion_api.Instance.get_all_types`.
The following nonsensical code snippet introduces the workflow:

.. code-block:: python

    try:
        sample_A = instance.get_sample(3)
        col = instance.get_root_collection().get_collection('Main Test')
        for sample in col.get_elements_of_iri(sample_A.json_ld['@type']):
            pass # DO something
    except requests.exceptions.RequestException as e:
        pass

Elements can also be found with the advanced search, see :doc:`Search`.

Elements in a list are only partially loaded. An element is loaded completely (one request per element) the first time its properties, segments, analyses or attachments are read or changed, so neither reading nor saving uses incomplete data. ``id``, ``name``, ``short_label`` and ``json_data`` are available without loading.
Elements accessed by index (``col.get_samples()[3]``) are loaded completely.

How to create Elements
******************************

To make a new entry in the ELN, you must first select the collection in which the element is to be created. Collection objects have the appropriate methods for creating objects.

The following methods can be used to create the standard objects. They create an empty object of their type; cell lines and SBMM samples need a little information up front.

The created object is not saved and must be saved explicitly so that the entry is transferred to the ELN.

* :meth:`chemotion_api.collection.Collection.new_sample`
* :meth:`chemotion_api.collection.Collection.new_reaction`
* :meth:`chemotion_api.collection.Collection.new_research_plan`
* :meth:`chemotion_api.collection.Collection.new_wellplate`
* :meth:`chemotion_api.collection.Collection.new_screen`
* :meth:`chemotion_api.collection.Collection.new_device_description`
* :meth:`chemotion_api.collection.Collection.new_cell_line` (material name and source)
* :meth:`chemotion_api.collection.Collection.new_sbmm_sample` (UniProt accession)

To create a generic element, the type must be specified as a parameter. Either by the human-readable label or by the system-internal name:

* :meth:`chemotion_api.collection.Collection.new_generic`
* :meth:`chemotion_api.collection.Collection.new_generic_by_label`

Since a sample cannot be created without a molecule (not by default at least), there is also the shortcut using the following methods

* :meth:`chemotion_api.collection.Collection.new_sample_smiles`
* :meth:`chemotion_api.collection.Collection.new_solvent`

And finally, all objects can be created using the IRI-based method:

* :meth:`chemotion_api.collection.Collection.new_element_by_iri`


.. code-block:: python

    try:
        col = instance.get_root_collection().get_collection('Main Test')
        sample = col.new_sample_smiles('CCO')
        sample.properties['external_label'] = 'Ethanol'
        sample.save()
    except requests.exceptions.RequestException as e:
        pass

How to work with Elements
********************************

All Objects have a set of common properties and methods:

* ``properties``: the data of the main tab of the element. The available keys are listed in the
  sections of the element types.
* ``segments``: the generic segments (tabs) of the element, see :doc:`Segments`.
* ``analyses``: the analyses tab, see :doc:`Analyses`.
* ``attachments``: the attached files, see :doc:`Attachments`.
* ``save()`` / ``load()``: writes the element to / reads it from the server.
* ``open()``: opens the saved element in a new tab of your web browser; ``url()`` returns its URL.

.. code-block:: python

    sample = instance.get_sample(3)
    sample.properties['description'] = 'Stored in the fridge'
    sample.save()
    # Check the result in the Chemotion web client (you need to be logged in in the browser)
    sample.open()

Restricted elements
-------------------

An element in a collection shared with you below the full detail level (10) comes with some fields
withheld by the server. :attr:`~chemotion_api.elements.abstract_element.AbstractElement.is_restricted`
tells you; withheld properties read as :data:`chemotion_api.utils.withheld.WITHHELD`, and
``save()`` refuses such an element with ``PermissionError`` (it would write placeholders over the
real values).

``WITHHELD`` is neither ``None`` nor a number. Test for it by identity, ``value is WITHHELD``.
Using it as a number — ``float()``, arithmetic, comparisons — raises ``WithheldValueError`` (a
``PermissionError``). It is also a ``str`` whose text is ``'***'``, the server's own mask, so the
element's raw ``json_data`` still serialises exactly as the server sent it. As a consequence,
``WITHHELD == '***'`` is true and ``isinstance(WITHHELD, str)`` too: compare by identity, not by
equality or type.

.. code-block:: python

    from chemotion_api.utils.withheld import WITHHELD

    for sample in shared_collection.get_samples():
        if sample.is_restricted and sample.properties['description'] is WITHHELD:
            print(sample.id, 'description withheld')

.. autodata:: chemotion_api.utils.withheld.WITHHELD
    :no-value:

.. autoexception:: chemotion_api.utils.withheld.WithheldValueError

Rich text
---------

Some properties are rich text in the ELN — a reaction's ``description`` and ``observation``, and the
``description`` of a wellplate or a screen. They are stored as `Quill deltas
<https://quilljs.com/docs/delta>`_, the ELN editor's format, and read as one;
:func:`~chemotion_api.quill_to_text` flattens it to text. Write a plain string — it is stored via
:func:`~chemotion_api.text_to_quill`, as a delta of the shape the ELN creates itself — or a
well-formed delta, so content read from the ELN (formatting included) can be written back. Anything
that is neither raises ``ValueError``.

.. code-block:: python

    from chemotion_api import quill_to_text

    reaction.properties['observation'] = 'Turned yellow after 5 min.
    reaction.save()
    print(quill_to_text(reaction.properties['description']))

.. autofunction:: chemotion_api.text_to_quill

.. autofunction:: chemotion_api.quill_to_text

===== docs/Examples.rst =====
Getting Started
================


Installation/Usage:
*******************
The package has been published on PyPi, it can be installed using pip.

.. warning::
   This is the **v4-only** release line. It requires a Chemotion ELN **v4** server and refuses to
   connect to anything else; for an ELN 3.1.x server install the ``312.x`` line instead. It needs
   Python 3.14. If the version published on PyPI is still from an older line, install from
   source as below.

.. note::
   Log in with an API token: create one in the ELN under *Account & Profile* → *Account* →
   *Authentication Token* (the ELN requires two-factor authentication for this) and pass it to :meth:`~chemotion_api.Instance.login_token`.
   :meth:`~chemotion_api.Instance.login` with a user name and password is deprecated, issues a

Example 1) Create a new Reaction
**************************************************
.. code-block:: python

    """
    This Example shows all necessary steps to create a new Reaction.

    1) We will login to a locally running Instance of chemotion
    2) We will create a new collection
    3) We will create 3 new samples and add some sample Properties
    4) We finally create a new Reaction.
    """
    import datetime

    from chemotion_api.elements.reaction import Reaction
    from chemotion_api.elements.sample import Sample
    from chemotion_api import Instance
    from chemotion_api.collection import RootCollection, Collection

    if __name__ == '__main__':
        # Initialize a new Instance connection
        instance = Instance('https://chemotion.dept.uni.de')
        try:
            # Test if the host is available and log in with your API token
            instance.test_connection().login_token('YOUR_API_TOKEN')
        except ConnectionError:
            # Exit if connection fails
            exit(1)
        except PermissionError:
            # Exit if Login fails
            exit(2)

        # Get root collection object
        root_col: RootCollection = instance.get_root_collection()
        # Get or create collection 'Main Test'
        mt_col: Collection = root_col.get_or_create_collection('Main Test')
        # Create a new Collection with the current date/time as label
        now_as_str = datetime.datetime.now().isoformat()
        project_col = mt_col.get_or_create_collection(now_as_str)

        # Create sample for Ammonium hydroxide
        sample_amm: Sample = project_col.new_sample_smiles('N.O')
        sample_amm.properties['external_label'] = "Ammonium hydroxide"
        sample_amm.save()
        # Create sample for Copper
        sample_copper: Sample = project_col.new_sample_smiles('[Cu]')
        sample_copper.properties['external_label'] = "Copper"
        sample_copper.save()
        # Create sample for product
        sample_res: Sample = project_col.new_sample_smiles('[Cu+2]([NH3])([NH3])([NH3])([NH3])[Cl-].[Cl-]')
        sample_res.save()

        # Create a new Reaction
        reaction: Reaction = project_col.new_reaction()

        # Add samples to the Reaction. Starting materials and reactants are added as splits,
        # products as copies of the samples.
        reaction.properties['starting_materials'].append(sample_amm)
        reaction.properties['reactants'].append(sample_copper)
        reaction.properties['products'].append(sample_res)

        # Add temperature profile to the Reaction
        reaction.properties['temperature'].add_time_point(hour=0,minute=0,second=0, temperature=50)
        reaction.properties['temperature'].add_time_point(hour=1,minute=0,second=0, temperature=100)
        # Save reaction
        reaction.save()

        me: Person = instance.get_user()
        # Create new group

===== docs/GenericElementsDetails.rst =====
Generic Elements
======================

Generic elements are element types defined by the administration of a Chemotion instance with LabIMotion.
They are loaded with :meth:`chemotion_api.Instance.get_generic_by_name` or
:meth:`chemotion_api.Instance.get_generic_by_label`, listed with
:meth:`chemotion_api.collection.Collection.get_generics_by_name` or
:meth:`chemotion_api.collection.Collection.get_generics_by_label`, and created with
:meth:`chemotion_api.collection.Collection.new_generic` or
:meth:`chemotion_api.collection.Collection.new_generic_by_label`.

Their templates can be loaded and edited with the :class:`chemotion_api.labImotion.GenericManager`
(:meth:`chemotion_api.Instance.generic_manager`). A template is a
:class:`chemotion_api.labImotion.GenericElementKlass` (formerly ``labImotion.GenericElement``); the element
exposes the label, name and version of its template as :attr:`~GenericElement.label`,
:attr:`~GenericElement.klass_name` and :attr:`~GenericElement.klass_version`.

The server sets the short label of a new element on its first save: the creator's initials, the template's
``klass_prefix`` and a counter of the user's elements of this type, e.g. ``API-WRK10``.

Layers and workflows
--------------------

Layers without fields appear in ``properties`` as empty dicts; :meth:`~GenericElement.layers_without_fields`
lists them. The generic segments of the element type are listed by ``elem.segments.available()``.

``properties`` holds the layers by their label: ``properties['Nr 1']['name_one']``. A layer that is used more
than once (e.g. in two workflows) gets a suffix taken from its layer key: the layer ``three.1`` is
``properties['Nr 3.1']``. The suffix belongs to the layer, so the names stay the same when the element is
saved and loaded again. Layers are ordered by position and workflow step.

The next steps of the workflows are listed by :meth:`~GenericElement.wf_next_options`; each option names its
workflow (``wf_idx``, ``wf_id``) and template layer (``layer_key``, ``layer_label``) and can be passed to
:meth:`~GenericElement.wf_next`, which returns the key of the new layer in ``properties``::

    option = next(o for o in elem.wf_next_options() if o['wf_idx'] == 1 and o['layer_label'] == 'Nr 4')
    key = elem.wf_next(**option)
    elem.properties[key]['name_four'] = 'done'

:meth:`~GenericElement.wf_workflows` lists the layers of each workflow with their ``properties`` key, and
:meth:`~GenericElement.wf_layer` returns a layer by workflow and label or key: ``elem.wf_layer(1, 'Nr 3')``.

Creating a template
-------------------

:meth:`~chemotion_api.labImotion.GenericManager.create_new_element` creates a template and returns it. By
default it releases an empty version 0.1 and activates the template; only released and active templates can
be used for new elements. Layers and fields are added to ``klass.properties``, and a new release makes them
available::

    from chemotion_api.labImotion.items.fields import FieldType
    from chemotion_api.labImotion.items.options import SaveActionType

    gm = instance.generic_manager()
    klass = gm.create_new_element('Micro Biology', 'bug', description='...', prefix='MB')
    general = klass.properties.add_new_layer('General')
    general.add_field(FieldType.TEXT, 'Strain')
    general.add_field(FieldType.SELECT, 'Growth medium', options=['LB', 'TB'])
    klass.properties.add_new_layer('Cultivation').add_field(FieldType.INTEGER, 'Temperature (°C)')
    klass.save(SaveActionType.MINOR)   # release; SaveActionType.DRAFT only stores the template

    elem = collection.new_generic_by_label('Micro Biology')
    elem.properties['General']['Strain'] = 'E. coli K12'
    elem.save()

Notes:

* Layer and field keys are generated from the labels (``'Temperature (°C)'`` -> ``temperature_c``) unless
  given with ``key=`` / ``field=``. Keys must be unique.
* A SELECT field uses a select option list of the template. ``options=[...]`` creates one for the field;
  shared lists are created with ``klass.properties.add_select_option(key, values)`` and linked by
  ``field.option_layers = key``.
* ``field.required`` and ``field.default`` are stored in the template.
* ``field.ontology`` links a field to an ontology term, like "Link to ontology terminology" in the template
  designer. Terms come from the TIB Terminology Service (NFDI4Chem collection), the same service the
  Chemotion UI uses: set a term ID (``'CHMO:0000593'``, short form or IRI; it is looked up online), a term
  dict from :meth:`~chemotion_api.labImotion.GenericManager.search_ontology_terms`, or ``None`` to remove the
  link. ``add_field(..., ontology=...)`` does the same. On elements, ``elem.field(layer, field).ontology``
  (and ``elem.segments.field(...).ontology``) returns the term of the template.
* Elements address their fields by the labels of the template version they were created with. After a
  label change, existing elements keep the old names; unknown names raise a ``ValueError`` on save.
* The ``description`` is stored as ``desc``; the short label prefix is ``klass.klass_prefix``.
* ``load_all_elements()`` skips templates that do not validate (with a warning); pass ``strict=True`` to
  :meth:`GenericElementKlass.load_all` to get the error instead.
* Element types are cached by the instance. :meth:`~chemotion_api.collection.Collection.new_generic_by_label`
  reloads them if a label is unknown; ``instance.element_manager.reload()`` does it explicitly.

User labels
***********

Chemotion shows coloured *user labels* on samples and reactions. On the wire an element carries
only the label **ids**, so reading ``properties['user_labels']`` gives you something like
``[3, 5]`` and nothing about what those mean.

To get the id-to-title map for the logged-in user:

.. code-block:: python

    for label in instance.get_user_labels():
        print(label.id, label.title, 'shared' if label.is_shared else 'private')

You see your own private labels plus every shared one, in the order the ELN itself displays them.

To resolve the labels *of a particular element*, use its ``user_labels_resolved`` property rather
than matching ids by hand:

.. code-block:: python

    sample = instance.get_sample(3)
    print(', '.join(label.display_title for label in sample.user_labels_resolved))

The label list is fetched **once per connection**, so resolving labels across hundreds of
elements costs a single request. The raw id list in ``properties['user_labels']`` is left
untouched, so an element can be resolved and saved without changing what goes back to the server.

An element may carry a label owned by another user, which the server will not return to you. That
is not an error: the id resolves to a placeholder :class:`~chemotion_api.user.UserLabel` with
``title`` ``None``, ``is_resolved`` ``False`` and ``display_title`` ``"#<id>"``. Prefer
``display_title`` over ``title`` when building strings, so an unresolvable label cannot break a
``join``.

To create a label, or change one of your own, use :meth:`~chemotion_api.Instance.save_user_label`.
The ELN overwrites every field a request leaves out, so the whole label is always sent; set every
field you want to keep. ``access_level`` is ``0`` for a private label and ``1`` or ``2`` for a
shared one. Put labels on an element through ``properties['user_labels']`` and save it.

.. code-block:: python

    from chemotion_api.user import UserLabel

    label = instance.save_user_label(UserLabel(title='Needs review', color='#d9534f', access_level=0))
    sample.properties['user_labels'] = list(sample.properties['user_labels'] or []) + [label.id]
    sample.save()

Errors
******

Requests the server refuses raise one of these. Each is also a ``ConnectionError``, so a broad
``except ConnectionError`` still catches them.

* :class:`~chemotion_api.connection.ChemotionRequestError`: the server answered with an error
  status (4xx). The message carries the status, the request and a short form of the reply.
* :class:`~chemotion_api.connection.ChemotionServerError`: a 5xx, usually the server failing on
  data it did not accept.
* :class:`~chemotion_api.connection.ChemotionRejectedError`: the server answered with a success
  status but said in the body that it did not do it (``{"errors": …}``, ``{"error": …}``,
  ``{"success": false}``). It is also a ``ValueError``; the decoded reply is in ``body``.

Before a request is sent:

* :class:`~chemotion_api.schema_manager.UnsupportedServerVersion`: the server is not an ELN v4.
* :class:`~chemotion_api.connection.TokenExpiredError` (a ``PermissionError``): the login token
  has expired; log in again.

Reading a field the server withheld from you, as a number, raises
:class:`~chemotion_api.utils.withheld.WithheldValueError` (a ``PermissionError``); see
:doc:`Elements`.

.. code-block:: python

    from chemotion_api.connection import ChemotionRejectedError

    admin = instance.get_user()            # logged in as an administrator

    try:
        device = admin.create_device('NMR 400', 'NMR')
    except ChemotionRejectedError as e:
        print('refused:', e.body)

Deleting elements
-----------------

``element.delete()`` and ``collection.delete_elements(*elements)`` delete the way the web UI does:
ELN v4 withdraws the elements from every collection you own and destroys only records left in no

===== docs/ReactionDetails.rst =====
Reaction
==========

A reaction has five material lists: starting materials, reactants, products, solvents and purification solvents
(:class:`chemotion_api.elements.reaction.MaterialList`). Adding a sample to the starting materials or reactants
adds a split of it, adding it to the products adds a copy.
:meth:`chemotion_api.elements.reaction.MaterialList.append_no_split` adds the sample itself. In both cases the
reaction, role and position of the sample are set and its amount is initialized. Saving the reaction recomputes the
equivalents (and the yields of the products) from the amounts and the reference material.

A sample can be in a reaction only once. Adding a sample the reaction already holds, in any of the five lists
(the same object or the same id), raises ``ValueError``: the ELN keeps one link per sample and would drop the
second entry on save. To move a sample to another role, remove it from its list first. A sample of another
reaction is accepted; on save the ELN gives this reaction a split of it, with a new id.

A sample's place in the reaction (reference, coefficient, waste and so on) is saved with the reaction;
see :doc:`SampleDetails`. ``rinchi_string`` and ``rinchi_web_key`` are computed by the ELN and cannot
be set.

Variations
----------

The variations tab of a reaction is accessible through :attr:`chemotion_api.elements.reaction.Reaction.variations`.
Each variation has a temperature, a duration, notes, the quantities of all materials and the values of the reaction
segments. Variations are saved with the reaction.

.. code-block:: python

    from chemotion_api.elements.utils import QuantityUnit

    reaction = instance.get_reaction(1)
    variation = reaction.variations.add_new()
    variation.properties['temperature']['value'] = 80
    variation.notes = 'Second run'

    # Quantities of the materials
    variation.starting_materials[0].set_quantity(2, QuantityUnit.Gram)
    variation.reactants[0].set_equivalent(1.5)
    variation.products[0].set_yield(85)  # in percent

    # Link an (already saved) analysis of the reaction
    variation.link_analyses(reaction.analyses.by_name('HPLC run 2'))

    # Segment values ({segment: {layer: {field: value}}})
    variation.segments['Electrochemistry']['Cell']['Electrode type'] = 'disk'
    variation.segments['Electrochemistry']['Cell']['Temperature'] = {'value': 25, 'unit': 'C'}
    reaction.save()

Only text, integer, select and system-defined segment fields can be varied. Select fields take the option key
or label, system-defined fields take ``{'value': ..., 'unit': ...}`` or a number in the field's default unit.
On save, every variation gets the same segments, as the Chemotion frontend builds the columns from them.
A system-defined field without a default unit in the segment template cannot be given a value in a
variation, since the frontend cannot show it.

Quantities of mixtures (:attr:`chemotion_api.elements.sample.Sample.is_mixture`) are not supported in
variations yet.

===== docs/SampleDetails.rst =====
Sample
==========

A sample is created in a collection, usually from a SMILES code
(:meth:`chemotion_api.collection.Collection.new_sample_smiles`), or as solvent from the predefined
solvent list (:meth:`chemotion_api.collection.Collection.new_solvent`).

The amount of a sample is set with :meth:`chemotion_api.elements.sample.Sample.set_amount`, in gram, liter or mol
(see :meth:`chemotion_api.elements.sample.Sample.allowed_quantity_units`). If the sample is part of a reaction,
this updates the equivalents of all reaction materials. The converted amount is available as
:attr:`chemotion_api.elements.sample.Sample.gram`, :attr:`chemotion_api.elements.sample.Sample.mol` and
:attr:`chemotion_api.elements.sample.Sample.liter`; each is ``None`` when the sample has no amount or it
cannot be converted (mol needs a molecular weight, liter a density or molarity).

.. code-block:: python

    from chemotion_api.elements.utils import QuantityUnit

    sample = col.new_sample_smiles('CCO')
    sample.properties['external_label'] = 'Ethanol'
    sample.set_amount(2.5, QuantityUnit.Gram)
    sample.save()

    # Set the amount of a starting material via its equivalent
    reaction = instance.get_reaction(1)
    reaction.reactants[0].set_amount(1.5, QuantityUnit.Equivalent)
    reaction.save()

Saving a sample that is part of a reaction
------------------------------------------

A sample's place in a reaction (``reference``, ``equivalent``, ``coefficient``, ``position``,
``waste``, ``show_label`` and the gas fields) is stored with the reaction, not with the sample. After
changing one of these, save the reaction: ``sample.save()`` raises ``ValueError``, because the ELN
would discard the change without an error.

.. code-block:: python

    reaction = instance.get_reaction(1)
    reaction.starting_materials[0].properties['coefficient'] = 2
    reaction.save()

A saved sample's ``short_label`` cannot be changed; the ELN assigns it and ignores changes to it.

Chemical inventory and safety data
----------------------------------

The ELN's *Chemicals* tab, with vendor, amounts, storage location and safety data, is a separate
record. :meth:`~chemotion_api.elements.sample.Sample.get_chemical` returns it as a
:class:`~chemotion_api.elements.sample.Chemical`. When the sample has none yet, ``exists`` is
``False`` and ``save()`` creates it.

.. code-block:: python

    chemical = sample.get_chemical()
    chemical.cas = '64-17-5'
    chemical.data['location'] = 'Cabinet 3'
    chemical.save()

Molecule names

A molecule is known by several names: IUPAC name, sum formula, and names users added. A sample

===== docs/SbmmSampleDetails.rst =====
SBMM sample
============

A sample of a sequence-based macromolecule, such as a protein. Create one with
:meth:`chemotion_api.collection.Collection.new_sbmm_sample`, giving a UniProt accession. Fetch one
with :meth:`chemotion_api.Instance.get_sbmm_sample` and list them with
:meth:`chemotion_api.collection.Collection.get_sbmm_samples`.

``properties`` holds the sample's own fields (``name``, ``external_label``, ``purity``,
``supplier`` and others). Quantities such as ``concentration``, ``molarity`` or ``activity`` are
``{'value': …, 'unit': …}`` pairs, like a sample's amounts. The protein is available as
``macromolecule`` and is read-only.

.. code-block:: python

    s = col.new_sbmm_sample(uniprot='P69905')
    s.properties['purity'] = 0.95
    s.properties['concentration'] = {'value': 2.0, 'unit': 'g/L'}
    s.save()
    print(s.macromolecule['short_name'])

.. note::
   **Limitations.** A new sample's protein can only be chosen by UniProt accession. Proteins that
   are not in UniProt, or modified variants of one, cannot be created from this client; create
   those in the ELN's web interface. Samples created there load and save normally, and their
   protein is sent back exactly as loaded. The protein of an existing sample is read-only here.
   If either limitation affects your work, please open an issue at
   https://github.com/Chemotion/chemotionapi/issues and describe what you need.

===== docs/ScreenDetails.rst =====
Screen
==========

A screen groups wellplates and research plans, for example the plates of one assay campaign.
Create one with :meth:`chemotion_api.collection.Collection.new_screen`, fetch one with
:meth:`chemotion_api.Instance.get_screen`, and list them with
:meth:`chemotion_api.collection.Collection.get_screens`.

``properties`` holds ``name``, ``collaborator``, ``requirements``, ``conditions``, ``result`` and
``description``. The description is rich text: assign a plain string or a Quill delta (see
:doc:`Elements`, *Rich text*).

The linked wellplates and research plans are id lists, ``wellplate_ids`` and
``research_plan_ids``. A save sends these lists as the new links, so they always hold the current
state, and an empty list removes every link. ``wellplates`` and ``research_plans`` load the
linked elements.

.. code-block:: python

    plate = col.new_wellplate()
    plate.save()

    screen = col.new_screen()
    screen.properties['name'] = 'Kinase panel'
    screen.properties['conditions'] = '37 °C, 24 h'
    screen.wellplate_ids.append(plate.id)
    screen.save()

    screen = instance.get_screen(screen.id)
    print([w.properties['name'] for w in screen.wellplates])

===== docs/Search.rst =====
Search
==========

The advanced search of Chemotion is available for samples (:meth:`chemotion_api.Instance.search_sample`)
and reactions (:meth:`chemotion_api.Instance.search_reaction`). Conditions are added with
``add_search_condition``; each condition has a match type and a connector that links it with the
conditions before it. :meth:`chemotion_api.search.search_helper.SearchHelperBase.request` runs the search
and returns an :class:`chemotion_api.elements.ElementSet`.

.. code-block:: python

    from chemotion_api.search.utils import EnumMatch, EnumConnector

    samples = (instance.search_sample()
               .add_search_condition(EnumMatch.LIKE, EnumConnector.OR, name='Ethanol')
               .add_search_condition(EnumMatch.EXACT, EnumConnector.AND, cas='64-17-5')
               .find_max(5)
               .request())
    for sample in samples:
        print(sample.short_label)

    reactions = (instance.search_reaction()
                 .add_search_condition(EnumMatch.BIGGER_THAN, EnumConnector.AND, temperature_in_c=30)
                 .request())

Conditions are combined with the connector (``AND`` / ``OR``); the connector is applied only
*between* conditions (the first condition's connector is ignored). Restrict the search to one
collection with ``in_collection(...)`` and cap the number of results with ``find_max(...)``.

===== docs/Segments.rst =====
Segments
==========

Segments are additional tabs of an element, defined with LabIMotion. All elements, including samples
and reactions, can have segments. A segment consists of layers, and each layer of fields. The values are
accessible through the ``segments`` property of an element: ``element.segments[segment][layer][field]``.
The segment, layer and field names are the labels shown in Chemotion; duplicate names get the suffix
``.1``, ``.2``, ...

``element.segments`` also contains the keys ``'Properties'`` and ``'Analyses'``, which are the same objects
as ``element.properties`` and ``element.analyses``.

A segment the element does not have yet is ``None``. Use ``segments.get(name)`` to add it with the default
values of the template.

.. code-block:: python

    sample = instance.get_sample(1)
    cell = sample.segments.get('Electrochemistry')['Cell']

    # Look up what a field accepts
    sample.segments.field_type('Electrochemistry', 'Cell', 'Electrode type')  # 'select'
    sample.segments.options('Electrochemistry', 'Cell', 'Electrode type')
    # [{'key': 'traditional', 'label': 'disk'}, {'key': 'mesh', 'label': 'mesh'}]
    sample.segments.units('Electrochemistry', 'Cell', 'Temperature')  # ['C', 'F', 'K']

    cell['Electrode type'] = 'disk'                      # key or label; stored as key
    cell['Temperature'] = {'value': 25, 'unit': 'C'}
    cell['Cycles'] = 3
    sample.save()

Values by field type
--------------------

* **select**: the option key. The option label is accepted as well and stored as key.
* **system-defined**: ``{'value': ..., 'unit': ...}``. A bare number gets the default unit of the field.
* **integer**: a whole number.
* **text** and other fields: stored as they are.

Changed select, system-defined and integer values are checked against the template when the element is saved;
an invalid value raises a ``ValueError``. Values loaded from the server are never rejected, even if they
do not fit the template anymore.

For segment values in reaction variations, see :doc:`ReactionDetails`.

Welcome to ChemotionAPI's documentation!
========================================

This is a python api for `Chemotion <https://chemotion.net/>`_. Chemotion is an Electronic Laboratory Notebook (ELN) developed at
the KIT. Chemotion is a web-based platform designed to help researchers manage and organize their experimental data in a secure and
efficient manner.

The ChemotionApi Python package is a wrapper for the RESTful API built on top of the Ruby on Rails
framework that allows users to interact with Chemotion ELN. The package provides a simple and intuitive
interface for creating, retrieving, updating, and deleting data stored in the ELN using Python. With
its RESTful architecture and comprehensive documentation, the ChemotionApi allows users to build custom applications and
workflows that leverage the ELN's capabilities and streamline their research processes.

.. important::
   **This release requires Chemotion ELN v4.** ELN 3.x and older are not supported: v4 rewrote
   collections and sharing, renumbered the share permission levels, and removed the
   ``/syncCollections`` API, so there is no meaningful overlap. Connecting to an older instance
   raises :class:`~chemotion_api.schema_manager.UnsupportedServerVersion` from
   :meth:`~chemotion_api.Instance.test_connection` — before any credentials are sent.

   **For an ELN 3.1.x server, use the** ``312.x`` **release line instead.** The package version
   tracks the server it targets: ``401.x.y`` ↔ ELN 4.0.x (from 4.0.1), ``312.x.y`` ↔ ELN 3.1.2,
   ``211.x.y`` ↔ ELN 2.1.1.

   This release is tested against ELN **v4.0.2**. ``.eln`` / RO-Crate export is not included.

.. note::
   **Element types.** Samples, reactions, wellplates, research plans, screens, cell lines, SBMM
   samples, device descriptions and LabIMotion generic elements can all be created, read, edited
   and moved between collections. Vessels (templates and instances) have their own classes in
   :mod:`chemotion_api.vessels`.

   **Acting immediately.** Element edits reach the server on ``save()``. Most other calls — moving,
   sharing, deleting, splitting, comments, references, exports, imports, reports, inventory data and
   administration — are sent right away. Deleting templates, users, groups or devices needs the
   item's label or abbreviation passed back as ``confirm=``.

.. note::
   **Log in with an API token.** Logging in with a user name and password is deprecated. See
   :meth:`~chemotion_api.Instance.login_token`.
